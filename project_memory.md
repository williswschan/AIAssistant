# Tech Cafe AI Helpdesk ??Project Memory

## Purpose
Standalone POC for ??Talk to Tech Cafe AI?? browser voice Help Desk using realtime speech-to-speech (S2S), later intended to sit beside the existing Tech Cafe Portal appointment flow.

## Key architectural decisions
- Transport: browser WebRTC to Azure OpenAI Realtime.
- Provider: **Azure OpenAI / Microsoft Foundry** (`foundry-techcafeaiassistant`, project `proj-techcafeaiassistant`) ??not OpenAI Platform and not chatgpt.com Advanced Voice.
- Auth pattern: Flask proxies session setup ??mint ephemeral `client_secrets` with permanent `api-key`, negotiate SDP to `/openai/v1/realtime/calls`, return **SDP answer only** to browser.
- Default model deployment: **`gpt-realtime-2.1`** (set in `.env` as `AZURE_OPENAI_REALTIME_DEPLOYMENT`; also available in Foundry: `gpt-realtime`, `gpt-realtime-mini`). Voice agent is Realtime 2.1, not the older `gpt-realtime` alone.
- Voice: `marin` (set via `AZURE_OPENAI_VOICE`). On voice switch: update `.env`, restart Flask, and ensure `/token` returns `voice` while browser `session.update` re-asserts `audio.output.voice` (required ??VAD-only update can leave timbre sounding wrong). Client pins `audio.output.voice` on every `response.create`, greets only after `session.updated` confirms voice, and prompt forbids mid-call voice/announcer-style switches (booking lines).
- Dual-model mode: voice = `gpt-realtime-2.1`; diagnostics tool `consult_helpdesk_expert` ??Flask ??Azure chat `gpt-6-astra`. Browser relays Realtime function calls; permanent key stays on server. Tool args include optional **`known_facts`** plus richer `already_tried` so Brain does not re-ask settled call facts (anti-double-ask). Post-consult voice coaching also strips re-asks.
- Prompt cache: **gpt-6-astra** uses explicit `prompt_cache_key` + `prompt_cache_retention` (24h) + startup warm-up. **Realtime voice** uses automatic in-memory caching when Azure supports it; app sets `truncation.retention_ratio=0.8` and logs `cached_tokens` from `response.done` when present.
- Post-consult speech: competing Realtime hold + tool reply caused mid-sentence cutoffs. Fix retained: cancel/clear before specialist reply, one `response.create` with speak_to_caller coaching. **Hold audio (option B):** continue-to-hold uses **Realtime/marin** again (local TTS only as fallback) so the caller hears one voice.
- Brain prompt caching: diagnose calls send a stable system prefix (`techcafe_prompt.txt` wrapper) with `prompt_cache_key` + `prompt_cache_retention=24h` (gpt-6-astra extended cache). Startup warm-up thread primes the cache. Logs `cached_tokens` on each diagnose.
- Expert-wait UX: voice prompt requires an explicit ??please hold / checking with diagnostic specialist??before the tool; while Brain runs, browser speaks continue-to-hold every **5s** (Realtime/marin; local SpeechSynthesis fallback; **English / Japanese / Mandarin / Cantonese** lines). Hold must stop the moment Brain returns. **Race (call-20260912-211033-1e05):** Brain returned in ~7s at 21:11:49; a late continue-to-hold `response.create` (English) was claimed as the specialist reply at 21:11:54, then coached Mandarin advice was suppressed ??~30s silence until barge-in. Fix: track `holdOutboundPending`, drain/cancel late holds before arming, never claim hold as `diagnoseOwnResponseId`, retry if own transcript still looks like a hold line.
- Post-Brain delivery: mute during kill (~1.2s) then drain holds then arm; first `response.created` after arm is the coached reply; unmute only on that id??s audio. Removed the 450ms ??too soon??cancel (it killed our own create ??silence in `call-20260912-164950-d12d`). Do not `response.cancel` extras while own is speaking.
- Auto hang-up: end_call must be paired with a real farewell. Client also schedules hangup when closing farewell speech is heard without the tool (call-20260913-132902-a0d2: Goodbye spoken, no end_call, call stayed open). Procedural lines still force a dedicated goodbye; barge-in during hangup does not abort ending.
- Turn detection: `server_vad` with `create_response` + `interrupt_response`. Session is created with both **false** so the greeting cannot be server-cancelled; after greeting audio ends the browser `session.update`s them back on (from `AZURE_INTERRUPT_RESPONSE` / token config) and clears the input buffer.
- Opening greeting: fixed `Hello, Tech Cafe IT Help Desk.` + one of 5 similar second lines chosen randomly per call in `app.js` (avoids immediate repeat via sessionStorage).
- Agent behavior: loaded from `techcafe_prompt.txt` into session instructions (not hard-coded in JS).
- UI: matches Tech Cafe Booking Portal look ? red gradient page, white rounded shell, red header/footer. Start/End buttons aligned with Azure VM look: red gradient rounded rects (~14.5rem), centered **AI Assistant** label + rainbow NEW ribbon on Start only; End Call same size/color without ribbon. Mic opens only after Start and is released on hang-up. Connecting ring: North American PSTN **ringback** (440+480 Hz, 2s on / 4s off); stops just before Hello. Greeting protected by **mic hold** + `turn_detection: null` until playback ends; then VAD/interrupt restored. `enableLocalPlayback` re-calls `remoteAudio.play()`.
- VM-only extras: Start click kickstarter (`window.__tcKick`) remains on the VM copy of `app.js` / HTML; local uses normal `app.js` click binding.
- Control WSS (`/ws/control`): client ping every **8s** + auto-reconnect on close. Console `Invalid frame header` usually means reverse proxy idle-closed the socket; if reconnect still drops mid-call, raise proxy WebSocket idle timeout on `ai.mymsngroup.com`.

## Important assumptions
- Azure Realtime deployment exists and region supports Realtime.
- Local Windows + Chrome/Edge for mic/WebRTC.
- ServiceNow and Tech Cafe booking remain simulated in the prompt.

## Non-obvious constraints
- ChatGPT Plus / Project instructions cannot drive a custom in-page voice button.
- Catalog model IDs ??usable until deployed in the Foundry project.
- Permanent keys must never ship to the browser; `.env` is gitignored.
- API key was shared in chat during setup ??rotate when practical.
